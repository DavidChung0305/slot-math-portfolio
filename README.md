# slot-math-portfolio：老虎機數學模型與模擬驗證

一款 5×3、243 Ways 老虎機的完整數學模型：從捲軸設定推導理論 RTP 與波動度，
並用 Excel、Python 窮舉、蒙地卡羅模擬三條獨立路徑交叉驗證。

| 指標 | 理論值 | 1,000 萬轉模擬 | 結果 |
|---|---:|---:|:---:|
| 總 RTP | 95.97% | 95.85% | ✓ z = −0.87 |
| 命中頻率 | 47.63% | 47.62% | ✓ z = −0.75 |
| 標準差 σ（押注倍數） | 4.30 | 4.29 | ✓ z = −0.59 |
| 免費遊戲觸發頻率（約每 117 轉 1 次） | 0.856% | 0.856% | ✓ z = −0.14 |

RTP 組成：主遊戲 69.26% ＋ 免費遊戲 26.71%（含重觸發）。pytest 16 個全部通過。

## 遊戲規格

設定全部在 [`config/game.json`](config/game.json)，Excel、Python 讀同一份。

| 項目 | 設定 |
|---|---|
| 盤面 | 5 軸 × 3 格，243 Ways（從軸 1 開始連續，相鄰軸有同符號即連線） |
| 押注 | 50 點（所有金額以整數點數計算） |
| 一般符號 | 高分 H1、H2、H3；低分 A、K、Q、J、T |
| Wild（W） | 只出現在軸 2–5，替代一般符號，本身不派彩 |
| Scatter（S） | 每軸 1 個，任意位置計數；3／4／5 個派 100／500／2500 點 |
| 免費遊戲 | 3／4／5 個 S 觸發 10／15／20 次，贏分 ×4，可重觸發 |
| 捲軸 | 每軸 30 格；高分符號較少（H1 2 個、H2／H3 各 3 個，低分各 4–5 個） |

設計取捨：
- **W 不放軸 1**：軸 1 決定這條路屬於哪個符號；若軸 1 有 W，同一條路可被多個符號認領、只能取最高，各符號就無法用「各軸個數相乘」分開計算。
- **高分符號放得少**：路數是各軸個數相乘，個數增加會被放大。例如每軸 H1 從 2 個增加到 4 個，H1 的 RTP 貢獻會從 5.5% 變成約 54%。

## 理論 vs 模擬：怎麼讀上面的表

完整結果（6 個指標＋派彩區間分佈）：[`docs/compare.md`](docs/compare.md)，由 `python -m sim.compare` 產生，不手動抄寫。

- **條件**：N = 10,000,000 轉，seed = 2026，任何人重跑都會得到相同數字。
- **檢定**：z = (模擬 − 理論) / SE，|z| ≤ 1.96 判定通過。
- **每個指標的 SE 不同**：
  - RTP：σ/√N（σ_total = 4.30 押注倍數）
  - 命中、觸發頻率：√(p(1−p)/N)
  - σ 本身：σ·√((κ−1)/(4N))。總贏分峰度 κ ≈ 407，尾端很重；若誤用常態假設（κ = 3），SE 會低估約 14 倍（√203），把正常的差距（0.59 SE）誤判成 8.4 SE。
- **唯一的 ✗**：派彩區間 (1,5] 的 z = −3.13。兩張表共 12 項檢定，程式完全正確時至少一項 ✗ 的機率約 1 − 0.95¹² ≈ 46%。換 seed 1–6 重跑，z 都在 ±1.2 以內，所以判斷是隨機波動，不是系統性錯誤。

## 驗證方法：三條獨立路徑

| 方法 | 怎麼算 | 能抓到 | 抓不到 |
|---|---|---|---|
| Excel PAR Sheet | 組合數＋公式 | 與 Python 比對：任一邊的實作錯誤 | 兩邊共用的模型錯誤 |
| Python 窮舉 | 逐盤結算全部 30⁵ 個盤面 | 與 Excel 比對：任一邊的實作錯誤 | 兩邊共用的模型錯誤 |
| 蒙地卡羅模擬 | 不用公式，照規則玩（含重觸發） | 模型錯誤（理論公式本身錯了） | 小於約 2 SE 的偏差 |

Excel ＝ Python ≈ 模擬，三方一致，才能說「模型和實作都對」。

pytest（16 個）涵蓋：
- 結算邊界：3／4／5 連、軸 1 沒有符號、中間軸斷掉、Scatter 剛好 2 個與 3 個、5 個 Scatter、最大連線贏分盤面
- 視窗計數：捲軸頭尾相接、W 加到每個一般符號
- 迴歸：全部盤面的總派彩點數、最大贏分與出現次數
- 理論 vs 模擬：100 萬轉固定 seed，|模擬 RTP − 理論| < 4 SE（固定 seed 避免 flaky test）

## 與 AI 協作

這個專案和 AI（Claude）一起完成。分工如下：

| 部分 | 誰做 |
|---|---|
| 遊戲設計決定（W 只放軸 2–5、免費轉 10／15／20 次、少次數高倍數 ×4） | 我 |
| 數學推導（重觸發、免費遊戲的變異數） | 我推導，卡住時 AI 給提示 |
| Excel PAR Sheet | 我建立工作表；部分公式由 AI 提供、我解釋後採用 |
| `exact.py`（窮舉結算） | 我撰寫，AI 逐段講解與審查 |
| `simulate.py`、`compare.py`、`export_par.py`、多數 pytest | AI 撰寫，我審查 |

**我怎麼驗證 AI 的結果：**
- AI 說的數字也只是一個待驗證的答案，要和上面三條獨立路徑比對。
- 三條路徑一致還不夠：如果 AI 一開始就誤解規則，三邊可能同樣都錯。所以規格（`game.json`）由我決定，並用手算小例子（例如 5 個 S 的盤面 = 2500 點）和從規則推出的邊界測試，確認程式符合我的規格。
- 突變測試：故意把程式改錯，確認測試真的會失敗。

**被抓到的例子：** AI 說軸 2 停在第 4 格時，視窗（A、W、S）裡 H1 的個數是 0。但程式輸出和 Excel 的 Window2 都是 1。原因是 AI 漏算了 W 會替代 H1。這次是靠 Excel 對照抓到的，現在已經寫成 pytest（`window_counts` 的 W 測試）。

## 數學重點

**1. 重觸發：平均免費轉數**

r = 每一次免費轉平均再觸發的免費轉次數 = Σₖ P(k 個 S)·次數ₖ ≈ 0.088（次／轉），需要 r < 1。

- 等比級數：觸發送 n 次 → 第 k 代平均 n·rᵏ 次 → 總共 n(1 + r + r² + …) = n/(1 − r)
- 第一步分析：令 m = 1 次免費轉連同其子孫的總轉數，m = 1 + r·m → m = 1/(1 − r)

**2. 模擬要跑多少轉：95% 信賴區間**

N 轉平均 RTP 的標準誤 = σ/√N（中央極限定理），95% 區間 = RTP ± 1.96·σ/√N。
本遊戲 σ = 4.30 押注倍數：N = 10⁷ 時半寬 ±0.27%；要達到 ±0.1% 需要 N ≥ (1.96·σ/0.001)² ≈ 7,100 萬轉。

**3. 驗證 σ：峰度修正**

樣本變異數 s² 是 (X − μ)² 的平均，它的變異數 Var((X − μ)²) = σ⁴(κ − 1)，需要四階動差。
由 delta method 得 SE(s) ≈ σ·√((κ − 1)/(4N))。老虎機總贏分 κ ≈ 407，比常態（κ = 3）大很多，SE(s) 是常態公式的 √203 ≈ 14 倍。

## 目錄結構與資料流

```
config/game.json                 唯一的遊戲設定（捲軸、賠率、Scatter、免費遊戲）
   │
   ├─→ excel/par_sheet_v1.xlsx   Power Query 讀 JSON → 組合數、Ways、RTP、命中頻率
   │
   └─→ python/
        ├─ slotmath/exact.py     窮舉 30⁵ 盤面：結算、RTP、σ、派彩區間（整數點數計算）
        ├─ sim/simulate.py       向量化蒙地卡羅模擬（numpy Generator、固定 seed、含重觸發）
        ├─ sim/export_par.py     輸出 excel/data/*.csv → Excel 的 Volatility 工作表
        ├─ sim/compare.py        理論 vs 模擬對照 → docs/compare.md
        └─ tests/test_exact.py   pytest 16 個
docs/rtp-tuning.md               調整 RTP 的作法與驗收流程
```

設計原則：
- **單一設定檔**：Excel 與 Python 讀同一份 `game.json`，不各自抄寫。
- **整數計算**：派彩以點數（整數）累加，最後才除以押注，避免浮點誤差累積。
- **可重現**：模擬一律用 `numpy.random.Generator` 並固定 seed。

