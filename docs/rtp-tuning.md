# RTP 調整作法（Tuning Playbook）

把「轉起來!」從總 RTP 61.27% 調到 95.97% 的完整過程，之後調任何數字都照這份做。

## 0. 先看現況

| 項目 | 調整前 | 目標 |
|---|---|---|
| 連線（Ways） | 49.25% | |
| Scatter 派彩 | 2.12% | |
| 主遊戲小計 | 51.37% | ~65–70% |
| 免費遊戲 | 9.91% | ~25–30% |
| **總 RTP** | **61.27%** | **~96%** |
| 命中頻率 | 47.63% | 不變 |
| σ_total | 2.03 | |

先看「差多少、差在哪一塊」，不要一開始就亂改數字。

## 1. 認識旋鈕：各自會動到什麼

| 旋鈕 | RTP | 命中頻率 | σ | 備註 |
|---|---|---|---|---|
| (1) 連線賠率 paytable | 成正比 | **不變** | 漲得慢（錢加在常見小獎） | 也會讓免費遊戲 RTP 跟著變 |
| (2) 捲軸組成 reels | 會變 | **唯一會變的** | 會變 | 牽動所有東西，最後才動 |
| (3) Scatter 派彩 | 會變 | 不變（命中頻率只看連線） | 中等 | 也會讓免費遊戲 RTP 跟著變 |
| (4) 免費遊戲次數 awards | 非線性（改 r） | 不變 | 中等 | r/(1−r)：重觸發會連鎖放大 |
| (5) 免費遊戲倍數 m | 免費遊戲部分成正比 | 不變 | 漲得最快（σ 幾乎跟著 ×m） | 必須是整數（金額用整數） |

**命中頻率只由「有沒有中」決定 → 只有捲軸組成會改變它。** 賠率只決定「中了付多少」。
例外：把某個賠率改成 0，或幫原本不付錢的組合加上賠率，等於改變了「中獎」的定義。

## 2. 單一旋鈕補到 96% 的比較（為什麼要組合）

| 做法 | 總 RTP | σ_total | 問題 |
|---|---|---|---|
| 只把連線賠率 ×1.6 | 96.52% | 3.09 | 主遊戲 ~80%、免費遊戲只有 ~10%，免費遊戲沒看頭 |
| 只把免費遊戲倍數 ×9 | 95.95% | 6.64 | 免費遊戲佔將近一半，波動太極端 |

錢放在**常發生的小獎** → σ 小；放在**很少發生的大獎** → σ 大。

## 3. 兩段式調整

### 3-1 先用賠率把主遊戲調到目標

連線 RTP 和賠率成正比：

```
主遊戲 = 連線 × k + Scatter
  68%  = 49.25% × k + 2.12%
    k  = 65.88 / 49.25 ≈ 1.34
```

### 3-2 免費遊戲會自己跟著變

```
RTP_FG = r/(1−r) × m × RTP_spin
```

RTP_spin 就是主遊戲 RTP（免費遊戲用同一套捲軸、同一張賠率表），所以主遊戲變大，免費遊戲也跟著變大：

```
r/(1−r) = 0.08795 / 0.91205 = 0.09643
調整前：0.09643 × 2 × 51.37% =  9.91%
調整後：0.09643 × 2 × 68.00% ≈ 13.11%   （Python 13.13%，差在四捨五入）
```

### 3-3 再用免費遊戲旋鈕補剩下的

13.1% → 28%，需要放大約 2.13 倍：

```
只動倍數：m = 2 × 28 / 13.13 ≈ 4.27 → 必須取整數 → m = 4（免費遊戲 26.25%）
只動次數：r ×2.13 → r/(1−r) 從 0.0964 變成 0.2305，放大 2.39 倍 > 2.13
          （分母 1−r 變小 = 重觸發變多），所以次數只要 ×1.94 左右
```

在 RTP 差不多的情況下，「多次數、低倍數」的 σ 會比「少次數、高倍數」略低
（m=2、19/29/39：免費遊戲 27.36%、σ 4.21；m=4、10/15/20：免費遊戲 26.25%、σ 4.23）。

**設計決定（勝）：方向 B — 少次數、高倍數（m = 4）**，免費遊戲短但刺激，「×4」好宣傳。

### 3-4 把賠率改成好看的整數，微調到 96%

在 ×1.34 附近挑整數，用 `total_moments` 逐組試算：

| 符號 | 調整前 3/4/5 連 | 調整後 3/4/5 連 |
|---|---|---|
| H1 | 50/150/500 | 70/200/700 |
| H2 | 30/100/300 | 40/140/400 |
| H3 | 20/60/200 | 30/80/250 |
| A | 10/30/100 | 15/40/140 |
| K | 10/30/100 | 15/40/140 |
| Q | 5/20/75 | 7/25/100 |
| J | 5/20/75 | 7/25/100 |
| T | 5/15/50 | 7/20/70 |

規則：高分符號 > 低分符號、A=K、Q=J 同分；Scatter 100/500/2500 和次數 10/15/20 不動；倍數 ×2 → ×4。

## 5. 改完之後的驗收流程（每次都要做）

1. 改 `config/game.json`
2. `cd python && ../.venv/Scripts/python.exe -m sim.export_par` → 更新 `excel/data/*.csv`
3. Excel「資料 → 全部重新整理」（或用 COM 自動執行）
4. **交叉驗證**：Python 和 Excel 的主遊戲總點數、主遊戲 RTP、總 RTP、命中頻率要完全一致
   - 這次：Excel 連線 815,705,640 + Scatter 25,758,000 = 841,463,640 = Python ✓
5. 跑 pytest：迴歸測試**應該**失敗 → 確認新數字已經和 Excel 對過 → 才更新測試的基準值
6. 模擬 RTP 要落在 95% 信賴區間內

## 6. 這次踩到的意外：最大贏分盤面換人了

舊賠率下，最大贏分是 5 個 S = 2500 點。新賠率下，pytest 抓到最大贏分變成 **3340 點**（12 盤）：

```
停止位置 [18, 3, 1, 4, 6]
   K  K  J  K  K
   H2 A  K  S  Q
   H1 W  W  W  W

H1：1 路 × 700 =  700
H2：1 路 × 400 =  400
K ：1·2·2·2·2 = 16 路 × 140 = 2240
合計 3340（舊賠率：500 + 300 + 16 × 100 = 2400 < 2500）
```

教訓：**「最大贏分盤面」是設定的性質，不是常數**。改了賠率就要重新窮舉；
如果測試只寫「5 個 S 是最大」，換賠率後就會默默失準。窮舉測試把它抓出來了。

**為什麼要在意（最大曝險）：** 3340 只是主遊戲的最大值；免費遊戲 ×4 → 13,360 點 = 267 倍押注，
再加上重觸發會更大（100 萬轉模擬最大 301 倍）。最大贏分決定賭場的準備金、是法規要揭露的規格（有些市場設上限），
尾端變長也推高 σ → 收斂到 RTP 需要的轉數 ∝ σ²（σ 2.03 → 4.30：同樣精度要 4.49 倍轉數）。

## 7. 可以重用的試算腳本骨架

```python
import copy
from slotmath.exact import load_config, total_moments, all_board_wins

base = load_config("../config/game.json")

def run(paytable, m, awards):
    c = copy.deepcopy(base)
    c["paytable"] = {s: {"3": v[0], "4": v[1], "5": v[2]} for s, v in paytable.items()}
    c["free_game"]["multiplier"] = m
    c["free_game"]["awards"] = {"3": awards[0], "4": awards[1], "5": awards[2]}
    main = all_board_wins(c).sum() / (30**5 * c["bet"])
    total, var, sd = total_moments(c)
    return main, total - main, total, sd   # 主遊戲、免費遊戲、總 RTP、σ
```

注意：賠率和倍數都必須是整數，`all_board_wins` 用整數陣列，float 會直接報錯。
