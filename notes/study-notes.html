01樣本空間與等機率

Day 3 · Q1

設定：5 軸，第 i 軸的捲軸帶長度為 Lᵢ。一次旋轉的結果是 5 個停止位置 (s₁, s₂, s₃, s₄, s₅)。

總組合數 = L₁ · L₂ · L₃ · L₄ · L₅            ← 乘法原理

要讓每種組合等機率，需要兩個假設

  1. 均勻：同一軸的 Lᵢ 個位置，每個機率都是 1/Lᵢ。
  2. 獨立：各軸停在哪裡互不影響。
P(s₁, s₂, s₃, s₄, s₅)
  = P(軸1停在s₁) × P(軸2停在s₂) × … × P(軸5停在s₅)   ← 獨立
  = (1/L₁) × (1/L₂) × (1/L₃) × (1/L₄) × (1/L₅)         ← 均勻
  = 1 / (L₁·L₂·L₃·L₄·L₅)
重點這兩個假設由 RNG 保證：每一轉為每軸各抽一個獨立、均勻落在 0 到 Lᵢ−1 的整數。程式寫成 rng.integers(0, L_i, size=N)。Day 18 會用卡方檢定驗證「均勻」。
陷阱：隨機不等於等機率2 軸，L₁ = 3、L₂ = 4。若軸 1 的位置 0 機率是 1/2（其他兩格各 1/4），則 P(軸1停0, 軸2停2) = 1/2 × 1/4 = 1/8，不是 1/12。獨立仍成立，失效的是均勻。這時候不能用「組合數 ÷ 總組合數」算機率，PAR Sheet 數組合數的做法也跟著失效。

面試時回答方式：先講出假設的名稱，再說每一步用到哪個假設。

02Lines 組合數：剛好 vs 至少

Day 3 · Q2

例：5 軸，每軸 Lᵢ = 10，A 在每軸出現 cᵢ = 2 次。只看一條線，A 從第 1 軸開始連續出現。

方法：每一軸各自數「合格的停法」，再相乘。

軸剛好 3 連剛好 4 連剛好 5 連
1–3是 A：cᵢ是 A：cᵢ是 A：cᵢ
4不是 A：L₄ − c₄是 A：c₄是 A：c₄
5不限：L₅不是 A：L₅ − c₅是 A：c₅
獎項一般式組合數機率
剛好 3 連 Ac₁c₂c₃(L₄−c₄)L₅6400.00640
剛好 4 連 Ac₁c₂c₃c₄(L₅−c₅)1280.00128
剛好 5 連 Ac₁c₂c₃c₄c₅320.00032
至少 3 連 Ac₁c₂c₃L₄L₅8000.00800
驗算技巧分項（剛好 3、4、5 連）加總，必須等於另一種算法（至少 3 連 = 前三軸是 A、後兩軸不限）。對不上就代表某一項算錯。Excel 步驟 4 的驗收就用這招。
陷阱：剛好 vs 至少2×2×2×2×10 = 160 是「至少 4 連」（= 128 + 32），把 5 連重複算進去了。「剛好 k 連」的第 k+1 軸一定要是「不是 A」。
預告 Day 4：加入 Wild 之後「剛好 3 連 A」的第 4 軸條件變成「既不是 A 也不是 Wild」，否則 Wild 會把連線延長成 4 連。L₄ − c₄ 要改寫。

03Ways 規則：不用連成一線

Day 3 · Q3 延伸

Ways 只看「每一軸的視窗裡有沒有該符號」，不管它在哪一列。仍然要從第 1 軸開始、相鄰連續。

軸1 軸2 軸3 軸4 軸5 列1 A · A · · 列2 · · · · · 列3 A A A · ·
  • Lines（只有中間一條線）：沒中獎。
  • Ways：軸 1 有 2 個 A、軸 2 有 1 個、軸 3 有 2 個、軸 4 沒有 → 3 連 A，共 2 × 1 × 2 = 4 路，派彩 = 4 × 賠率。

「路」= 從每一軸各挑一個 A 連成一條路徑的挑法數。5×3 盤面每軸可走 3 列，共 3⁵ = 243 條路徑，所以叫 243 Ways。

LinesWays
判斷方式只看固定幾條線上的符號只看每軸視窗有沒有該符號
位置必須在線上任何列都可以
同軸多個相同符號不影響路數相乘
5×3 的線數自訂（例如 20 線）等同 243 條

04雙重計數：每個 A 被看到幾次

Day 3 · Q3

問題：第 i 軸長 Lᵢ、A 有 cᵢ 個、視窗 3 列，捲軸帶頭尾相接。把 Lᵢ 個停止位置的「視窗內 A 個數」全部加起來是多少？

小例子：捲軸帶 [A, K, A, Q, J]，L = 5、c = 2。打勾表的列是停止位置，欄是每個 A：

停止位置 s視窗內容位置 0 的 A位置 2 的 A列合計
0A, K, A✓✓2
1K, A, Q✓1
2A, Q, J✓1
3Q, J, A✓1
4J, A, K✓1
欄合計336
  • 橫著加：2+1+1+1+1，每列不同，看不出規律。
  • 直著加：每個 A 都剛好被 3 個視窗看到（視窗有 3 格），所以總和 = 3 × c。
視窗 3 列：總和 = 3cᵢ
視窗 4 列：總和 = 4cᵢ
E[Xᵢ] = 總和 / Lᵢ = 3cᵢ / Lᵢ       ← Xᵢ = 第 i 軸視窗內 A 的個數；用到均勻假設
重點雙重計數：同一張表，橫著加和直著加一定相等，挑好算的方向。頭尾相接保證沒有 A 因為在邊緣而少算。

05期望值：平均值，什麼時候等於機率

Day 3 · Q3 延伸

期望值永遠是「平均值」。只有當隨機變數只會是 0 或 1 時，平均值剛好等於機率。

隨機變數可能的值期望值的意義
Xᵢ（視窗內 A 的個數）0, 1, 2, 3平均每個視窗有幾個 A
1{X₄ = 0}（指示函數）0 或 1機率 P(X₄ = 0)
 
E[1{X₄=0}] = 0 × P(X₄≠0) + 1 × P(X₄=0) = P(X₄=0)

總和 = 總組合數 × 期望值

E[路數] = Σ (每種組合的路數 × 1/總組合數)     ← 均勻：每種組合機率相同
        = (Σ 每種組合的路數) / 總組合數        ← 常數提到 Σ 外面
        = 總和 / 總組合數
⇒ 總和 = 總組合數 × E[路數]

白話：平均值 = 總和 ÷ 個數。

06Ways：剛好 3 連 A 的路數總和

Day 3 · Q3 延伸

一盤的路數 = X₁ · X₂ · X₃ · 1{X₄=0}

總和 = 總組合數 × E[X₁·X₂·X₃·1{X₄=0}]
     = (L₁L₂L₃L₄L₅) × E[X₁]·E[X₂]·E[X₃]·P(X₄=0)          ← 獨立：乘積的期望 = 期望的乘積
     = (L₁L₂L₃L₄L₅) × (3c₁/L₁)·(3c₂/L₂)·(3c₃/L₃)·(N₄/L₄)
     = 3c₁ · 3c₂ · 3c₃ · N₄ · L₅                           ← L₁~L₄ 約掉

N₄ = 第 4 軸「視窗裡沒有 A」的停止位置個數。第 5 軸不限，所以留下 L₅。

和 RTP 的關係E[X₁X₂X₃·1{X₄=0}] = 平均每轉中幾路「剛好 3 連 A」。乘上 3 連 A 的賠率，就是這個獎項對 RTP 的貢獻。Day 4 把每個獎項的貢獻加總就是主遊戲 RTP。

07陷阱：P(X = 0) ≠ 1 − 3c/L

Day 3 · Q3 延伸

用 [A, K, A, Q, J]（L = 5、c = 2）代入：

1 − 3c/L = 1 − 6/5 = −0.2          ← 負的機率，不可能
實際：每個視窗都至少有 1 個 A ⇒ N = 0，P(X=0) = 0

錯在哪：把平均個數當成機率

E[X]     = 1×P(X=1) + 2×P(X=2) + 3×P(X=3)
P(X ≥ 1) = 1×P(X=1) + 1×P(X=2) + 1×P(X=3)

例：E[X] = 6/5 = 1.2   ← s=0 的視窗有 2 個 A，算了 2 次
    P(X≥1) = 5/5 = 1

一般：E[X] ≥ P(X ≥ 1)，只有沒有任何視窗含 2 個以上 A 時才相等
結論N 不能只用個數 c 算，取決於 A 在捲軸帶上的排列。Excel 做法：每個停止位置用 3 格 COUNTIF 算視窗內 A 個數，再 COUNTIF 數「= 0」的列數。所以 Ways 的 PAR Sheet 一定要有完整的捲軸帶排列。

08間隔通式：N 怎麼算，捷徑何時成立

Day 3 · Q3 延伸，對照 ezslotdesign slotmath4 的堆疊例

P(X = 0) = 這一軸停下來後，視窗裡完全看不到 A 的機率 = N / L。在 Ways「剛好 3 連」中，第 4 軸就是用這一項表示「斷掉」，角色和 Lines 的 (L₄ − c₄)/L₄ 相同。

把捲軸帶看成圓圈，相鄰兩個 A 之間夾的非 A 格數叫間隔 g，c 個 A 有 c 個間隔。看不到 A 的視窗 = 連續 3 格都不是 A，一定完整落在某個間隔裡；長度 g 的間隔放得下 g − 2 個這種視窗。

N = Σ max(0, gⱼ − 2)               ← 對每個間隔 j 加總（視窗 r 列時是 gⱼ − (r−1)）

例 1：[A, K, A, Q, J]，間隔 1 和 2
      N = max(0,−1) + max(0,0) = 0                         ✓
例 2：長度 10，2 個 Q 堆疊在 0、1，間隔 0 和 8
      N = 0 + 6 = 6，P(X=0) = 0.6                           ✓
      捷徑 10 − 2×3 = 4 是錯的（重疊的視窗被扣了兩次）

捷徑 L − 3c 什麼時候正確

L = c + Σ gⱼ
L − 3c = Σ (gⱼ − 2)               ← c 個間隔各分到一個 −2
真正的 N = Σ max(0, gⱼ − 2)
gⱼ ≥ 2 時兩者逐項相等；gⱼ < 2 時捷徑那一項是負的，會少算
結論捷徑正確 ⇔ 每個間隔 g ≥ 列數 − 1，也就是任兩個 A 的距離 ≥ 列數。距離剛好等於列數就夠了，不用「超過」。
實作不需要迴圈。Excel 逐列 COUNTIF 往下拉；Python 用 NumPy 把捲軸帶頭尾接起來，一次算出所有視窗（向量化，Day 7）。
對 RTP 的影響E[Xᵢ] = 3cᵢ/Lᵢ 只看個數；P(Xᵢ = 0) = Nᵢ/Lᵢ 看排列。「剛好 k 連」需要第 k+1 軸斷掉，所以個數相同、排列不同的兩款遊戲，RTP 可以不同。堆疊會讓「看不到」的機率變高，但一看到就是多個，路數一次乘很大：中獎變少、單次變大，波動度上升（Day 6 驗證）。

09派彩規則：Lines 和 Ways 怎麼結算

Day 3 第 2 步，對照 ezslotdesign slotmath4

LinesWays
結算單位每條線各自結算，再加總每個符號結算一次，所有路合併
同一線／路上只算最長只算最長
同一盤不同線可各自派彩（可同時中 3 連和 2 連）同一符號只有一個結果：最長連數 × 路數
起點都必須從第 1 軸開始、相鄰連續

練習盤面（賠率 A：2 連 2、3 連 10、4 連 50；Lines 只有 3 條水平線）：

軸1 軸2 軸3 軸4 軸5 列1 A A K Q J 列2 K A A J Q 列3 Q J A K A
Lines：列1 A A → 2 連 = 2；列2 第1軸是 K → 0（中間的 A A 不算）；列3 → 0；合計 2
Ways ：A 個數 1, 2, 2, 0 → 3 連，1×2×2 = 4 路，派彩 4 × 10 = 40
為什麼只算最長2 連是 3 連的前半段，兩個都派等於同一條路付兩次錢。更重要的是：「剛好 3/4/5 連」必須互斥，RTP 才能把各獎項直接加總。
陷阱Lines 贏 2、Ways 贏 40 不能直接比，兩者押注不同。比較 RTP 前要先除以每轉押注。
決定（2026-11-12）作品集遊戲採用 5×3、243 Ways。理由：沿用 Xᵢ、N 與間隔通式；面試展示度較高；Python 逐軸數符號再相乘，向量化自然。

10遊戲設定檔 config/game.json

Day 3 第 3 步

Excel（PAR Sheet）、Python（模擬）、C#（結算引擎）都讀同一份設定。只有一份資料來源，理論值和模擬值對不上時，就一定是邏輯錯誤，不是設定不一致。

欄位內容用途
name轉起來!報表標題
layout5 軸 × 3 列視窗取幾格
bet50 點RTP = E[派彩] / bet
symbolsH1 H2 H3（high）、A K Q J T（low）符號清單、排序
paytable每符號 3/4/5 連，點數／每路派彩 = 賠率 × 路數
reels5 條 × 30 格cᵢ、N、Xᵢ；模擬取視窗

物件還是陣列

用名字查 → 物件 {}（C# 的 Dictionary／class）；用位置查或順序有意義 → 陣列 []（C# 的 List）。

  • layout 物件：兩個數字意義不同，[5, 3] 看不出哪個是軸。
  • reels 陣列中的陣列：軸的順序有意義（從第 1 軸連）；位置就是停止位置，順序一換 N 和 RTP 就變。
  • paytable 物件中的物件：paytable["H1"]["5"]。JSON 物件的鍵只能是字串，所以寫 "3"。

為什麼押注 50、賠率用點數

小獎約是押注的 0.1 倍，「倍數」無法用整數記錄
押注 = 50 點，賠率 = 每路幾點（整數）
一盤派彩 = Σ 各符號（賠率 × 路數）      ← 全是整數乘加，沒有浮點誤差
RTP = E[一盤派彩] / 50
陷阱：驗收能過不代表正確symbols 寫成兩個 J、漏了 T，但「有 8 個符號」的檢查仍然通過。要加上一致性檢查：symbols 的 id = paytable 的鍵 ⊇ 捲軸上出現的符號。這類檢查之後放進 pytest 和 CI。

捲軸帶第一版：每軸 H1 2、H2 3、H3 3、A K Q 各 4、J T 各 5，同符號間距 ≥ 3（L − 3c 捷徑成立，Excel 可交叉驗算）。

11Excel PAR Sheet：匯入與計數

Day 3 第 4 步（4-1、4-2）· excel/par_sheet_v1.xlsx

Power Query：Excel 直接讀 config

Excel 內建的資料匯入工具，存的是「去哪裡讀、怎麼整理」的步驟，不是資料本身。改了 game.json 之後按「資料 → 全部重新整理」就同步。開啟：資料 → 取得資料 → 從其他來源 → 空白查詢 → 進階編輯器。

let
    Source  = Json.Document(File.Contents("...\config\game.json")),   ← json.load
    Reels   = Source[reels],                                           ← g["reels"]
    Tbl     = Table.FromColumns(Reels, {"Reel1",...,"Reel5"}),         ← 每軸一欄
    WithPos = Table.AddIndexColumn(Tbl, "Pos", 0, 1, Int64.Type),      ← 停止位置 0~29
    Result  = Table.ReorderColumns(WithPos, {"Pos","Reel1",...})
in
    Result

Counts 表：各軸符號個數 cᵢ

B2 = COUNTIF(Reels[Reel1], $A2)      ← 往右拉 Reel1→Reel2…；往下拉 $A2→$A3…
B10 = SUM(B2:B9)                      ← 每軸合計必須是 30
寫法往右拉往下拉
A2變 B2 ✗A3 ✓
$A2$A2 ✓$A3 ✓
A$2B$2 ✗A$2 ✗
$A$2$A$2$A$2 ✗

$ 鎖住它後面那一部分。符號名稱都在 A 欄（鎖欄），但要跟著列走（不鎖列）。

陷阱：符號名稱 H1 是儲存格位址公式寫 COUNTIF(..., H1) 會被讀成 H 欄第 1 列（空白），結果是 0。要參照寫著符號名稱的儲存格，或加雙引號。
陷阱：差一列也會「看起來對」B 欄公式指到 $A1，整欄錯一列；H3、K、Q、T 的數字剛好和上一個符號相同，看起來正確。是 Total = 30 的檢查列抓到的。合計列就是 PAR Sheet 的自我驗算。
驗收方式用 Python（openpyxl）讀 xlsx，逐格和 game.json 比對：Reels 5 軸 × 30 格順序一致；Counts 每格 = JSON 的計數、合計 30。Excel 編輯中（還在輸入儲存格）按 Ctrl+S 不會存檔，先按 Enter 或 Esc。

12Window 表：環狀視窗與逐格驗算

Day 3 第 4 步（4-3）· excel/par_sheet_v1.xlsx 的 Window1–Window5

MOD：取餘數，處理頭尾相接

捲軸是一個圈，像時鐘：11 點再過 3 小時是 2 點，不是 14 點。MOD(x, L) 是 x 除以 L 的餘數，結果永遠在 0 到 L−1。

MOD(7, 3) = 1     MOD(9, 3) = 0     MOD(2, 3) = 2

位置編號 1~L，停在 p，往下第 k 格：
  MOD(p − 1 + k, L) + 1      ← 先減 1、取餘數、再加 1

第 1 列 = p
第 2 列 = MOD(p, L) + 1
第 3 列 = MOD(p + 1, L) + 1

驗算（L = 30）：p = 29 → 29, 30, 1    p = 30 → 30, 1, 2
陷阱：MOD(30, 30) = 0，捲軸沒有第 0 格直接寫 MOD(p + 1, 30) 時，p = 29 會得到 0。MOD 的範圍是 0~29，編號卻是 1~30，差 1 要先減後加。Python 的索引從 0 開始，直接寫 (p + k) % L 即可。

Window 表的欄位

A      Pos 1~30
B–D    Row1–3 位置編號    =A2、=MOD(A2, $G$2) + 1、=MOD(A2+1, $G$2) + 1
G2     L                  =COUNTA(Reels[Reel1])          ← 不寫死 30
I–K    Sym1–3 符號        =INDEX(Reels[Reel1], B2)       ← 第幾個 → 符號
M–T    8 符號個數         =COUNTIF($I2:$K2, M$1)         ← 鎖欄範圍、鎖列表頭
第 33 列  Sum             =SUM(M2:M31)                   ← 應 = 3c
第 34 列  N               =COUNTIF(M2:M31, 0)            ← 應 = L − 3c（間距 ≥ 3 時）

INDEX(一排資料, 第幾個) 像打開第幾號置物櫃。COUNTA 數非空白格數，讓捲軸長度從設定來，規格改成 32 格時公式一格都不用改。Reel 2–5 用「移動或複製 → 建立複本」，再用 Ctrl+H 把 Reel1 換成 Reel2…（搜尋範圍選「工作表」，查詢選「公式」），每張應取代 91 筆 = 90 格 INDEX + 1 格 COUNTA。

陷阱：看 Excel 列號找位置，差一格表頭佔第 1 列，所以列號 = Pos + 1。INDEX 數的是資料第幾個，要看 Pos 欄。這種錯叫 off-by-one（差一錯誤）。
陷阱：表格參照往右拖會換軸Reels[Reel1] 往右拖，Excel 自動變成 Reel2、Reel3。不會報錯、每格都是正常符號，只有逐格比對 JSON 才抓得到。
陷阱：看不見的空格表頭打成「 Q」（前面有空格），COUNTIF 一個都數不到。
陷阱：各軸組成相同，Sum／N 驗不出換軸5 軸每個符號個數都一樣，所以 Sum、N 都相同。要看特定位置的符號（如 Pos 5、Pos 30）才分得出是哪一軸。
結果5 軸 × 8 符號全部符合 Sum = 3c、N = L − 3c；openpyxl 逐格比對 game.json 通過（位置公式、INDEX、COUNTIF、摘要列）。Sum 永遠等於 3c；N = L − 3c 只在同符號間距 ≥ 列數時成立，所以逐格數才是基準，捷徑是交叉驗算。

13RTP：定義與推導

Day 4 第 1 步

名詞

  • 軸（reel，捲軸）：畫面上直的一條，會轉動、停下。5×3 = 5 軸，每軸露出 3 列。
  • 捲軸帶（reel strip）：每軸背後一條依序印著符號、頭尾相接的帶子；本遊戲每條 30 格（game.json 的 reels、Excel 的 Reels 表）。
  • 停止位置：一軸停在捲軸帶的第幾格，每軸 30 種；玩家看到從這格往下 3 格（視窗，見第 12 節）。
  • RTP（Return to Player，返還率）：玩家每押 1 元，平均拿回多少。RTP 96% = 押 100 平均拿回 96。
  • 莊家優勢（house edge）= 1 − RTP。
  • 停輪組合：5 軸各停在哪一格的一種情況。總數 T = L₁L₂L₃L₄L₅ = 30⁵ = 24,300,000。
  • W：一轉的派彩，是隨機變數。

推導

1. 所有結果：T = 30⁵ 種停輪組合
2. 各軸均勻 + 獨立（RNG 保證）→ 每種組合機率 = 1/T
3. 期望值定義：E[W] = Σ w(組合) × (1/T)
                    = (1/T) × Σ w(組合)      ← 機率相同，提出來
                    = 總派彩 ÷ T
4. 除以押注：RTP = E[W] ÷ bet = 總派彩 ÷ (T × bet)

直覺：每種組合各轉一次，總押注 T × bet、總派彩 Σw，相除即 RTP。

小例子

1 軸 4 格，押注 50，只有第 4 格派 100：
  w = 0, 0, 0, 100
  公式：  100 ÷ (4 × 50) = 0.5
  期望值：E[W] = 100 × 1/4 = 25，25 ÷ 50 = 0.5   ✓

和 Ways 路數的關係

Ways 每一路付一次錢：
  總派彩 = Σ（各獎項總路數 × 每路賠率）
  RTP    = 總派彩 ÷ (30⁵ × 50)
陷阱：總派彩是錢的加總，不是中獎盤面數總派彩 = 每種組合的派彩金額全部相加（沒中獎的是 0）。例：w = 0, 30, 0, 100 → 總派彩 130 點；中獎盤面 2 個。「中獎盤面數 ÷ 總組合數」是命中頻率（hit frequency），這例是 2/4 = 50%。RTP 衡量平均拿回多少，命中頻率衡量多常中，兩者不同。
前提：等機率直接除以 T 只在每種組合機率相同時成立。RNG 不均勻就要用各自的機率加權（Day 18 卡方檢定驗證均勻性）。
RTP 是長期平均大數法則保證轉得夠多時，實際返還率接近 RTP；短期偏離多少由波動度決定（Day 6）。

Day 4 第 1 步

乘法原理

分步驟做選擇、每一步的選法互不影響時，總數 = 各步選法數相乘。Ways 的一路 = 從軸 1 開始每軸視窗挑一個該符號。

軸1 有 2 個 H1、軸2 有 2 個、軸3 有 1 個、軸4 沒有
剛好 3 連 H1 = 2 × 2 × 1 = 4 路

全部盤面的總路數

一個盤面：路數 = x₁ × x₂ × x₃ × [x₄ = 0] × 1     （xᵢ = 第 i 軸視窗裡的個數）

全部 30⁵ 盤面加總，各軸獨立 → 五層加總可拆開：
  Σ(x₁ x₂ x₃ [x₄=0] · 1) = Sum₁ × Sum₂ × Sum₃ × N₄ × L₅

Sumᵢ = 第 i 軸 30 個停止位置的視窗個數加總（= 3cᵢ）
N₄   = 第 4 軸看不到該符號的停止位置數
L₅   = 第 5 軸停止位置總數（停哪都行）

H1：6 × 6 × 6 × 24 × 30 = 155,520 路
派彩：155,520 × 50 = 7,776,000 點

拆開的道理和 (a+b)(c+d) = ac + ad + bc + bd 相同：先乘再加 = 先加再乘。

陷阱：最後一軸用 L，不是 Sum剛好 3 連只要求軸 4 斷掉，軸 5 停哪都算 1 次，所以乘 L₅ = 30。用 Sum 會變成「軸 5 也要有 H1」。

加入 Wild（百搭符號）

Wild（W）可以代替任何一般符號。同一個 W 可以同時幫好幾個符號湊成連線，所以會拉高 RTP 和命中頻率。

盤面：  軸1 K/T/A   軸2 W/K/Q   軸3 A/K/H1   軸4 Q/J/T
  3 連 K：1 × (K + W = 2) × 1 = 2 路
  3 連 A：1 × (W = 1)     × 1 = 1 路     ← 同一個 W 同時幫 K 和 A

公式形狀不變，把「K」換成「K 或 W」：
  剛好 3 連 K = Sum₁ × Sum₂ × Sum₃ × N₄ × L₅
  Sumᵢ = 第 i 軸視窗裡「K 或 W」的個數加總 = 3(c_K + c_W)（間距夠時）
  Nᵢ   = 第 i 軸視窗裡「沒有 K 也沒有 W」的停止位置數

ezslotdesign 寫法：WK·WK·WK·X_WK，WK = K 或 Wild，X_WK = 既非 K 也非 Wild
陷阱：斷掉的軸出現 W 就沒斷軸 4 有 W 時，W 當 K，3 連變 4 連。所以 N 要排除 K 和 W 兩者。
總派彩= Σ（各獎項總路數 × 每路賠率），再代入 RTP = 總派彩 ÷ (30⁵ × 50)。

15面試問答

先自己口頭答一遍，再展開看重點

老虎機每種停輪組合為什麼等機率？由誰保證？
需要「各軸位置均勻」和「各軸獨立」兩個假設，由 RNG 保證：每軸獨立抽一個 0 到 Lᵢ−1 的均勻整數。機率 = 1/(L₁L₂L₃L₄L₅)。可用卡方檢定驗證均勻性。
Lines 遊戲「剛好 3 連」和「至少 3 連」的組合數怎麼算？怎麼驗算？
剛好 3 連：c₁c₂c₃(L₄−c₄)L₅。至少 3 連：c₁c₂c₃L₄L₅。驗算：剛好 3、4、5 連加總 = 至少 3 連。
Lines 和 Ways 差在哪？243 Ways 的 243 怎麼來？
Lines 只看固定線上的符號；Ways 只看每軸視窗有沒有該符號，同軸多個要路數相乘。5×3 每軸 3 列，3⁵ = 243。
為什麼 P(視窗沒有 A) 不能寫成 1 − 3c/L？
3c/L 是視窗內 A 的平均個數 E[X]，不是 P(X ≥ 1)。一個視窗有 2 個 A 時，E[X] 會算 2 次。反例 [A,K,A,Q,J] 會算出 −0.2。
在什麼條件下，1 − 3c/L 會剛好等於 P(X = 0)？用 A 在捲軸帶上的間距描述。
任兩個 A 的距離 ≥ 列數（間隔 g ≥ 列數 − 1），這時沒有視窗能同時看到兩個 A。證明：L − 3c = Σ(gⱼ − 2)，真正的 N = Σ max(0, gⱼ − 2)，所有 gⱼ ≥ 2 時逐項相等。
長度 10 的捲軸帶有 2 個 Q 堆疊，視窗 3 列。看不到 Q 的停止位置有幾個？為什麼不是 10 − 2×3？
6 個。間隔是 0 和 8，N = 0 + (8 − 2) = 6。10 − 6 = 4 是錯的，因為同時看到兩個 Q 的視窗被扣了兩次。
兩款 Ways 遊戲捲軸帶長度、每軸 A 的個數都相同，為什麼 RTP 可能不同？
A 的排列間隔不同 → N 不同 → P(X = 0) 不同。E[X] = 3c/L 只看個數，但「剛好 k 連」需要第 k+1 軸斷掉，用的是 P(X = 0)，所以各獎項機率和 RTP 都會不同。
Ways 盤面上 A 形成 3 連時，前兩軸的 2 連為什麼不另外派彩？
2 連是同一條路的前半段，兩個都派等於重複付錢；而且「剛好 k 連」必須互斥，RTP 才能直接加總各獎項。Lines 也一樣：同一條線只算最長，只是不同線可以各自派彩。
為什麼 Excel、Python、C# 要讀同一份設定檔？
理論和模擬對不上時，可能是 (a) 設定不一致、(b) 結算邏輯寫錯、(c) 統計誤差。單一設定檔排除 (a)，直接鎖定 (b) 或 (c)。注意：它抓不到「遊戲設計不好」，因為兩邊會一致地算出同樣的數字。
押注為什麼設 50 點而不是 1？
讓押注零頭的小獎（0.1 倍）也能用整數表示。結算和大量模擬全程整數累加，避免浮點誤差，最後才除以 50 得到 RTP。附帶效果：押 1 又要整數賠率的話，最小獎至少 1 倍押注，243 Ways 的 RTP 會遠超過 100%。
Excel 和 Python 怎麼保證用的是同一份設定？
Excel 用 Power Query 直接讀 config/game.json，存的是讀取步驟不是資料；改設定後重新整理就同步。Python 用 json.load 讀同一個檔案。
你怎麼確認 PAR Sheet 的計數沒有算錯？
兩層：表內自我驗算（每軸合計 = 30；剛好 3/4/5 連加總 = 至少 3 連；逐列數的 N = 間距 ≥ 3 時的 L − 3c 捷徑），以及用 Python 讀 xlsx 和 game.json 逐格比對。曾抓到公式錯一列、但部分數字巧合正確的 bug。
RTP 怎麼定義？為什麼可以用「總派彩 ÷ (總組合數 × 押注)」算？
定義：RTP = E[W] ÷ bet，每押 1 元平均拿回多少。因為各軸均勻且獨立，每種停輪組合機率都是 1/T，E[W] = Σw × (1/T) = 總派彩 ÷ T，所以 RTP = 總派彩 ÷ (T × bet)，等於「每種組合各轉一次」的總派彩除以總押注。前提是等機率。例：T = 30⁵、bet = 50、總派彩 1,166,400,000 → RTP = 0.96。
把押注從 50 降到 16（等於賠率全部放大約 3 倍），RTP 和命中頻率各會怎樣？
RTP 反比放大：0.28738 × 50/16 ≈ 0.898。命中頻率不變，因為連線規則和捲軸沒改，每個盤面有沒有中獎都一樣，只是中獎時拿回的倍數變大。所以 RTP 相同的遊戲手感可能完全不同，要看派彩怎麼分配（波動度，Day 6）。押注必須是整數：往上取整 RTP 會略低（16 → 89.8%）。
捲軸有兩個 J 只隔 2 格（位置 5 和 7），看不到 J 的停止位置數 N 會比 L − 3c 多還是少？視窗內 J 的總個數呢？
N 比較多。位置 5 的 J 被停止位置 3、4、5 看到，位置 7 的 J 被 5、6、7 看到，停在 5 重疊，看得到 J 的只有 5 個停止位置，N = L − 3c + 1（重疊幾個多幾個）。但總個數仍是 3c，因為停在 5 那格是 2，重疊被算在同一格裡。
捲軸頭尾相接怎麼算視窗？規格改成 32 格，你的模型要改哪裡？
往下第 k 格 = MOD(p − 1 + k, L) + 1（0 起算則是 (p + k) % L）。L 用 COUNTA 從設定讀，不寫死，所以只要改 game.json 再重新整理，公式不用動。寫死的數字會漏改，而且漏改不報錯、只會默默算錯。
